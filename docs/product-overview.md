# Caravel 产品介绍与功能说明

## 产品定位

**Caravel 是面向多项目、多任务开发者的本地优先多 AI 编码 Agent 指挥台。当前公开版本支持 macOS，覆盖 Apple Silicon 与 Intel。**

它将 Claude Code、Codex、OpenCode、pi、Grok 等编码 Agent 集中到一个桌面工作台中，帮助用户统一派发任务、跟踪进度、处理授权、审查代码并完成交付。本机尚未安装的 Agent 可在设置里一键安装或升级。

Caravel 不替代 Agent、模型或代码编辑器。用户继续使用自己的 Agent CLI、模型账号和 IDE，Caravel 负责把分散的 Agent、项目、会话和代码改动组织成清晰、可控的任务工作流。

## 为什么需要 Caravel

只运行一两个 Agent 任务时，CLI 简单直接。但当用户同时维护多个项目、并行运行多个 Agent 后，终端和会话很快变得难以管理：不知道哪个任务还在运行、哪个正在等待确认、哪个会话属于哪个项目，也难以及时续接任务和统一验收代码。

用户不得不在脑中维护一张隐形表格：哪个终端对应哪个项目、使用哪个 Agent、正在做什么、是否需要介入、最后修改了哪些代码。真正的瓶颈从“Agent 能不能完成任务”，变成了“人能不能管理这些 Agent”。

Caravel 将原本散落在终端里的执行过程组织成可追踪的任务。一个任务包含目标、工作区、Agent、持续会话、运行状态和最终代码改动；用户在一个工作台中完成派发、监控、干预和验收，把注意力放在目标和决策上。

## 核心价值

- **统一管理**：在一个工作台中管理多个 Agent、项目和并行任务。
- **过程可见**：随时了解任务进度、Agent 动作、待处理事项和最终结果。
- **交付可控**：通过权限确认、代码审查和验收机制控制 Agent 对项目的影响。
- **经验复用**：把高质量提示词、技能、解决经验和成功流程沉淀为可复用资产。
- **持续改进**：通过成本洞察和 AI 复盘，发现协作问题并优化使用方式。
- **就地扩展**：用定时器、数据库、小应用把重复工作和常用工具留在同一工作台。

## 功能架构

| 层级 | 能力领域 | 核心作用 |
|---|---|---|
| 核心工作流 | 多 Agent 指挥、任务协作、安全交付、移动协同 | 管理从任务派发、过程干预到代码验收的完整链路 |
| 自动化与编排 | 定时自动化、工作流编排 | 将重复任务和复杂流程交给 Agent 按计划执行 |
| 经验与效能 | 提示词、技能、经验库、洞察台、复盘台 | 复用有效方法，衡量效果、成本和运行健康 |
| 配套开发工具 | 编辑器、数据库、待办、收件箱、剪贴板、我的应用 | 在同一工作台中完成常用开发与个人效率工作 |
| 设置与环境 | Agent、插件、模型、权限与本机维护 | 统一管理 Agent 运行所需的工具、能力和偏好 |

## 功能说明

### 1. 工作台

统一创建和管理多个 AI Agent 任务，可通过列表、看板或分屏实时查看进度。

- 统一管理 Claude Code、Codex、OpenCode、pi、Grok
- 从对话、授权确认到计划、子 Agent 进展、代码 Diff 审查和最终交付，都在同一页面完成
- 助手回复逐 token 流式预览，实时看到 Agent 的思考与产出
- 任务可关联多个工作区，并汇总直接与间接相关任务
- 对话消息可复制为文本或图片，方便分享完整回复
- 被应用中断的任务会标为待续接，进入后可继续原会话
- 可随时停止任务或转到终端继续处理

### 2. 任务库

集中保存和查找全部历史任务。

- 按状态、Agent、工作区、日期及是否有关联任务等条件筛选
- 支持搜索、收藏、归档和分组管理
- 支持同步已有 Agent 会话，统一纳入管理
- 同时提供工作区打开、Git 分支、提交、推送和冲突处理入口

### 3. 定时器

把每天、每周、每隔一段时间或只做一次的事交给它自动跑，不必自己守着点。

- **一句话创建**：用自然语言说出时间和要做什么，解析后回填表单让你确认，不会直接创建
- **也可手动填写**名称、内容和周期
- **周期**：每天、每周、每隔几分钟或几小时、只跑一次
- **多时刻**：每天或每周可设多个时刻，例如早上 9:30 和晚上 8:30 各跑一次
- **工作时段**：间隔任务可限制在指定工作日和工作时间内
- **三种执行方式**
  - 本地提醒：到点弹出提醒，不调用 Agent
  - 本地脚本：由 Agent 生成并试跑，之后按时执行本地脚本，不再重复调用 Agent；支持 shell 与 PowerShell
  - Agent 执行：到点按任务描述派发编码 Agent
- **错过补跑**：电脑当时没开时，可选择回来后补跑
- **立即运行**：不必等到点，可手动跑一次看效果
- **跑完处理**：可回看运行记录和产出，也可弹出提醒卡片
- **管理**：可暂停、编辑、删除；列表或卡片两种陈列，顶部显示下一次何时跑

### 4. 编辑器

浏览、搜索和编辑项目文件，减少在外部编辑器之间来回切换。

- 多标签页、语法高亮、自动保存
- Markdown、Mermaid 图表与图片预览，也可直接粘贴文件或目录路径打开
- 查看、定位和回滚相对上次提交的改动；Diff 中可直接对照图片版本
- 文件速览可打开完整 Diff，并使用常用 Git 操作

### 5. 数据库

连接 MySQL、PostgreSQL、SQLite、MongoDB 或 Redis 后，在工作台里查数和改数。

- 浏览对象、筛选分页数据；SQLite 连本地文件，MongoDB 查文档，Redis 管 Key
- 编写和执行 SQL 或文档查询，查看、编辑或全量导出结果，结果也可导出为 SQL
- 连续对话式 SQL Copilot 可统一生成、解释、优化和修复语句
- 支持收藏查询、参数化执行、执行历史和对象定义
- 可通过 MCP 把数据库能力交给 Agent
- 生产库危险操作会先确认，变更前能看到目标表规模

### 6. 待办板、收件箱与剪贴板

个人事项和随手材料不用另开应用。

- **待办板**：待处理、进行中、已完成三种状态；支持标签、有效期、子待办、图片和附件；待办可一键转为 AI 任务，并自动跟随任务完成
- **收件箱**：随手记录暂时不需要整理的想法、问题和资料，可加标签、图片和文件
- **剪贴板**：自动记录文本、代码、JSON 和图片历史，支持搜索、分类、收藏和常用片段

### 7. 提示词、技能与经验库

把有效的指令、工具和避坑经验留下来，下次直接用。

- **提示词**：分组管理，支持变量、置顶以及预绑定技能和 MCP；创建任务或继续对话时可用按钮或 `/` 命令插入
- **技能与 MCP**：为任务组合专业能力和外部工具；技能依赖的 MCP 会自动带入任务和工作流
- **经验库**：记录解决方法、适用场景和避坑规则，可手动整理，也可从复盘一键沉淀

### 8. 工作流

把 Agent 执行、命令操作和人工确认编排成可重复运行的流程。

- 为不同步骤指定角色、模型、技能和任务要求
- 支持变量、自动推进、人工确认、失败重试、步骤跳转和运行中止
- 可将现有任务接入工作流继续推进
- 可从一次成功的 Agent 对话中提炼可复用工作流
- 保留运行记录，方便回看每次执行

### 9. 洞察台与复盘台

不只记录 Agent 做了什么，还帮助判断是否有效、花了多少钱、下次怎么改。

- **洞察台**：查看任务效率、Agent 与模型表现、工具使用、成本与用量、权限安全和运行健康
- 成本可按金额或 Token 对比上一周期，并按 Agent、模型、工作区或标签下钻
- 运行健康可分 Agent 查看安装、数据、内存和 CPU 占用
- **复盘台**：按时间、工作区和标签汇总多项任务，由 AI 生成带证据的成果、问题和下一步建议
- 报告可导出，也可把结论沉淀为提示词、经验、工作流或技能
- 对单条回复点赞或点踩，按模型汇总好评率

### 10. 我的应用

把个人常用小工具留在同一个工作台里。

- 用一句话描述想要的小工具，AI 就能把它做出来，例如日报助手或数据看板
- 也可以把网址或本地网页添加为链接应用，在窗口内直接打开
- 应用可以联网取数、读写你选中的文件、发通知或查看任务，用之前都会先征求同意
- 做好后可以继续改进、保存版本、导出分享

### 11. 独立分支与安全交付

把“Agent 能执行”与“代码可交付”分开。Agent 可以自主完成工作，但关键权限和最终代码仍由用户决定。

- 支持在隔离副本中完成代码修改，避免直接影响原项目
- 在工作区查看独立分支改动、浏览副本文件，并安全移除本地副本
- 设置中可清理已结束且无风险的隔离副本，任务与远程分支保留供续接
- 对敏感操作发起授权确认，用户可选择单次或持续放行
- 集中展示代码变更，验收通过后再合并，不符合预期时可直接放弃

### 12. 设置

集中管理偏好与运行环境。

- **Agent**：配置可用 Agent、模型、权限，以及默认选择
- **安装与配套工具**：一键安装或升级本机 Agent，以及 Git、Node、cc-switch 等配套工具；升级会识别并沿用当前安装来源
- **插件**：统一管理 Claude、Codex 与 OpenCode 插件，并在任务中选用
- **默认终端**：选择打开终端或接管 Agent 时使用的终端
- **界面外观**：切换主题、任务状态动效和界面缩放
- **功能管理**：控制左侧各功能入口是否显示，并支持拖拽排序
- **技能管理**：查看不同 Agent 的技能与 MCP
- **远程控制**：配置飞书连接、智能对话和消息记录
- **环境维护**：检查更新、查看运行环境、清理隔离副本和服务日志

### 13. 飞书远程协同

离开电脑时，仍可通过飞书查看任务进展并处理关键节点，无需配置公网地址。

- 查看任务状态和 Agent 进度
- 创建任务和继续对话
- 处理权限确认与任务验收
- 接收关键状态通知

## 典型使用流程

1. 在设置中安装需要的 Agent，选择项目，描述目标，并指定合适的 Agent。
2. Agent 开始执行，用户在工作台统一查看多个任务的进度。
3. 遇到敏感操作或需要决策时，Caravel 提醒用户确认。
4. Agent 完成后，用户集中审查代码变更并决定合并、继续修改或放弃。
5. 将有效的提示词、解决经验或任务流程沉淀为提示词、经验或工作流。
6. 重复事项交给定时器：一句话说清时间和做法，确认后按时自动跑。
7. 通过复盘与成本洞察持续优化后续的人机协作方式。
8. 需要个人小工具或常用网页时，用「我的应用」生成或添加。

## 适用场景

- 同时使用多个 AI 编码 Agent 的个人开发者
- 需要并行推进多个项目或编码任务的工程师
- 希望让 Agent 自主执行、同时保留代码控制权的用户
- 需要反复执行代码检查、问题修复或发布流程的开发者
- 希望沉淀个人提示词、经验和 AI 协作方法的重度用户
- 关注 Agent 效率、成本和交付质量的技术负责人
- 需要定时提醒、本地脚本、数据库操作或个人小工具，又不想离开工作台的用户

## 产品特点

### 本地优先

任务、对话记录、工作区信息和个人知识资产由本机应用统一管理。用户掌握自己的项目数据，并自主决定是否启用飞书等远程能力。

### Agent 开放

Caravel 不绑定单一 Agent。用户可以根据模型能力、任务类型和使用习惯选择不同工具，在设置中安装或升级，并在统一的产品体验中管理它们。

### 人负责决策，Agent 负责执行

Caravel 的重点不是让 Agent 完全取代开发者，而是把人从重复执行中释放出来，同时保留目标设定、权限判断、代码审查和最终验收等关键决策权。

## 一句话总结

**Caravel 让多个 AI 编码 Agent 从分散的命令行工具，变成可统一指挥、可安全验收、可持续复用的开发生产力。**
